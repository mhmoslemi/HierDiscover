@triton.jit
def triton_tri_mul_kernel(
    left_ptr, right_ptr, out_ptr,
    B, N, H,
    stride_left_b, stride_left_i, stride_left_k, stride_left_h,
    stride_right_b, stride_right_i, stride_right_k, stride_right_h,
    stride_out_b, stride_out_i, stride_out_j, stride_out_h,
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):
    # program ids
    pid_m = tl.program_id(0)  # row (i)
    pid_n = tl.program_id(1)  # col (j)
    pid_head = tl.program_id(2)  # batch * head

    # compute batch and head indices
    batch_idx = pid_head // H
    head_idx = pid_head % H

    # linear base ptr offset for this batch/head
    left_base = left_ptr + batch_idx * stride_left_b + head_idx * stride_left_h
    right_base = right_ptr + batch_idx * stride_right_b + head_idx * stride_right_h
    out_base = out_ptr + batch_idx * stride_out_b + head_idx * stride_out_h

    # start indices
    i_start = pid_m * BLOCK_M
    j_start = pid_n * BLOCK_N

    # Create offsets
    i_range = i_start + tl.arange(0, BLOCK_M)
    j_range = j_start + tl.arange(0, BLOCK_N)

    # masks for out-of-bounds i/j
    i_mask = i_range < N
    j_mask = j_range < N

    # allocate accumulator
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # loop over k dimension
    for k_iter in range(tl.cdiv(N, BLOCK_K)):
        k_start = k_iter * BLOCK_K
        k_range = k_start + tl.arange(0, BLOCK_K)
        k_mask = k_range < N

        # Load A tile: shape (BLOCK_M, BLOCK_K)
        # left indexing: left[batch, i, k, head]
        a_ptrs = left_base + i_range[:, None] * stride_left_i + k_range[None, :] * stride_left_k
        a = tl.load(a_ptrs, mask=i_mask[:, None] & k_mask[None, :], other=0.0)
        a = a.to(tl.float32)

        # Load B_T tile: shape (BLOCK_K, BLOCK_N)
        # right indexing: right[batch, j, k, head] -> need transpose.
        # Use pointer: right_base + k_offset * stride_right_k + j_offset * stride_right_i

        b = b.to(tl.float32)

        # Dot product: (M,K) x (K,N) -> (M,N)
        acc += tl.dot(a, b)

    # Store result
    out_ptrs = out_base + i_range[:, None] * stride_out_i + j_range[None, :] * stride_out_j

"""
TriMul “outgoing” implementation (AlphaFold‑3 style).

The forward pass consists of:
1. Layer‑Norm over the channel dimension.
2. Two linear projections (left/right) and three gating projections.
3. Optional element‑wise mask.
4. Gated left/right tensors.
5. Core O(N³) operation:
      out[b,i,j,h] = Σₖ left[b,i,k,h] * right[b,j,k,h]
   – implemented as a batched GEMM C = A @ Bᵀ with a Triton kernel.
   – each (batch, head) pair is processed independently; the kernel tiles the
     output matrix (i‑j plane) and accumulates over K‑tiles.
6. Layer‑Norm on the hidden dimension, multiplicative out‑gate, and final linear
   projection back to the original dimension.

The Triton kernel loads `left` and the transposed view of `right` on‑the‑fly,
accumulates in FP32 (inputs may be FP16) and writes the result in FP32.
Block sizes (128×128×32) have been chosen for H100‑class GPUs.
"""

import torch
import triton
import triton.language as tl
from typing import Tuple, Dict

# ----------------------------------------------------------------------------- #
# Triton kernel for the O(N³) einsum:   out = Σₖ left[..., i, k, h] * right[..., j, k, h]
# ----------------------------------------------------------------------------- #
@triton.jit
def tri_mul_outgoing_kernel(
    left_ptr, right_ptr, out_ptr,                # pointers
    B, N, H,                                     # problem size
    stride_l_b, stride_l_i, stride_l_k, stride_l_h,   # left strides
    stride_r_b, stride_r_i, stride_r_k, stride_r_h,   # right strides
    stride_o_b, stride_o_i, stride_o_j, stride_o_h,   # out strides
    BLOCK_M: tl.constexpr, BLOCK_N: tl.constexpr, BLOCK_K: tl.constexpr,
):
    # -----------------------------------------------------------------
    #  Program IDs
    # -----------------------------------------------------------------
    pid_m = tl.program_id(0)   # row tile (i)
    pid_n = tl.program_id(1)   # col tile (j)
    pid_head = tl.program_id(2)  # combined batch‑head index

    batch_idx = pid_head // H
    head_idx  = pid_head % H

    # Base pointers for this (batch, head) slice
    left_base  = left_ptr  + batch_idx * stride_l_b + head_idx * stride_l_h
    right_base = right_ptr + batch_idx * stride_r_b + head_idx * stride_r_h
    out_base   = out_ptr   + batch_idx * stride_o_b + head_idx * stride_o_h

    # -----------------------------------------------------------------
    #  Tile coordinates
    # -----------------------------------------------------------------
    i_start = pid_m * BLOCK_M
    j_start = pid_n * BLOCK_N

    i_range = i_start + tl.arange(0, BLOCK_M)
    j_range = j_start + tl.arange(0, BLOCK_N)

    i_mask = i_range < N
    j_mask = j_range < N

    # Accumulator in FP32
    acc = tl.zeros((BLOCK_M, BLOCK_N), dtype=tl.float32)

    # -----------------------------------------------------------------
    #  Loop over K dimension
    # -----------------------------------------------------------------
    for k_iter in range(tl.cdiv(N, BLOCK_K)):
        k_start = k_iter * BLOCK_K
        k_range = k_start + tl.arange(0, BLOCK_K)
        k_mask = k_range < N

        # left tile: shape (BLOCK_M, BLOCK_K)  -> left[batch, i, k, head]
        a_ptrs = left_base \
                 + i_range[:, None] * stride_l_i \
                 + k_range[None, :] * stride_l_k
        a = tl.load(a_ptrs,
                    mask=(i_mask[:, None] & k_mask[None, :]),
                    other=0.0).to(tl.float32)

        # right tile (transposed): shape (BLOCK_K, BLOCK_N)
        # we need right[batch, j, k, head] accessed as Bᵀ[k, j]
        b_ptrs = right_base \
                 + k_range[:, None] * stride_r_k \
                 + j_range[None, :] * stride_r_i
        b = tl.load(b_ptrs,
                    mask=(k_mask[:, None] & j_mask[None, :]),
                    other=0.0).to(tl.float32)

        # GEMM on the tile
        acc += tl.dot(a, b)

    # -----------------------------------------------------------------
    #  Store the result
    # -----------------------------------------------------------------
    out_ptrs = out_base \
               + i_range[:, None] * stride_o_i \
               + j_range[None, :] * stride_o_j
    tl.store(out_ptrs, acc, mask=(i_mask[:, None] & j_mask[None, :]))


# ----------------------------------------------------------------------------- #
# Helper that launches the Triton kernel
# ----------------------------------------------------------------------------- #
def tri_mul_outgoing_triton(left: torch.Tensor, right: torch.Tensor) -> torch.Tensor:
    """
    left / right: [B, N, N, H]  (any floating dtype, typically FP16/FP32)
    Returns: out of same shape, dtype FP32
    """
    assert left.shape == right.shape
    B, N, _, H = left.shape
    device = left.device

    # Output tensor (FP32)
    out = torch.empty_like(left, dtype=torch.float32, device=device)

    # Choose block sizes (tuned for H100 – feel free to adjust)
    BLOCK_M = 128
    BLOCK_N = 128
    BLOCK_K = 32   # small enough to keep shared memory low

    # Strides (in elements, not bytes)
    stride_l_b, stride_l_i, stride_l_k, stride_l_h = left.stride()
    stride_r_b, stride_r_i, stride_r_k, stride_r_h = right.stride()
    stride_o_b, stride_o_i, stride_o_j, stride_o_h = out.stride()

    # Grid: (tiles over i, tiles over j, batch*head)
    grid = (
        (N + BLOCK_M - 1) // BLOCK_M,
        (N + BLOCK_N - 1) // BLOCK_N,
        B * H,
    )

    tri_mul_outgoing_kernel[grid](
        left_ptr=left,
        right_ptr=right,
        out_ptr=out,
        B=B,
        N=N,
        H=H,
        stride_l_b=int(stride_l_b),
        stride_l_i=int(stride_l_i),
        stride_l_k=int(stride_l_k),
        stride_l_h=int(stride_l_h),
        stride_r_b=int(stride_r_b),
        stride_r_i=int(stride_r_i),
        stride_r_k=int(stride_r_k),
        stride_r_h=int(stride_r_h),
        stride_o_b=int(stride_o_b),
        stride_o_i=int(stride_o_i),
        stride_o_j=int(stride_o_j),
        stride_o_h=int(stride_o_h),
        BLOCK_M=BLOCK_M,
        BLOCK_N=BLOCK_N,
        BLOCK_K=BLOCK_K,
        num_warps=8,          # H100 benefits from many warps
    )

    return out

    # -----------------------------------------------------------------
    #  1) Input layer‑norm over the channel dimension
    # -----------------------------------------------------------------
    x = torch.nn.functional.layer_norm(
        input_tensor,
        normalized_shape=(dim,),
        weight=weights["norm.weight"],
        bias=weights["norm.bias"],
        eps=eps,
    )

    # -----------------------------------------------------------------
    #  2) Linear projections (no bias)
    # -----------------------------------------------------------------
    left_proj = torch.nn.functional.linear(x, weights["left_proj.weight"])
    right_proj = torch.nn.functional.linear(x, weights["right_proj.weight"])

    # -----------------------------------------------------------------
    #  3) Optional mask (mask shape [B, N, N])
    # -----------------------------------------------------------------
    if not config.get("nomask", False):
        # Ensure mask has same dtype as projections for correct broadcasting
        mask_broadcast = mask_tensor.unsqueeze(-1).type_as(left_proj)
        left_proj = left_proj * mask_broadcast
        right_proj = right_proj * mask_broadcast

    # -----------------------------------------------------------------
    #  4) Gating (sigmoid of linear transforms of the **normed** x)
    # -----------------------------------------------------------------
    left_gate = torch.nn.functional.linear(x, weights["left_gate.weight"]).sigmoid()
    right_gate = torch.nn.functional.linear(x, weights["right_gate.weight"]).sigmoid()
    out_gate = torch.nn.functional.linear(x, weights["out_gate.weight"]).sigmoid()

    # Apply gates
    left = left_proj * left_gate
    right = right_proj * right_gate

    # -----------------------------------------------------------------
    #  5) Core TriMul (batched A @ Bᵀ) – launch Triton kernel
    # -----------------------------------------------------------------
    # Cast to FP16 for the kernel (lighter memory traffic); kernel accumulates in FP32.
    left_fp16 = left.to(torch.float16)
    right_fp16 = right.to(torch.float16)

    # Triton computes the O(N³) term; result is FP32.
    out_hidden = tri_mul_outgoing_triton(left_fp16, right_fp16)  # [B,N,N,hidden]

    # -----------------------------------------------------------------
    #  6) Output layer‑norm on hidden dimension
    # -----------------------------------------------------------------
    out_hidden = torch.nn.functional.layer_norm(
        out_hidden,
        normalized_shape=(hidden_dim,),
        weight=weights["to_out_norm.weight"],
        bias=weights["to_out_norm.bias"],
        eps=eps,
    )

    # Apply multiplicative out‑gate (same shape as out_hidden)
    out_hidden = out_hidden * out_gate

    # -----------------------------------------------------------------
    #  7) Final linear projection back to original dimensionality
    # -----------------------------------------------------------------
    output = torch.nn.functional.linear(out_hidden, weights["to_out.weight"])

    return output
```

**Explanation of key design points**

* **Mixed‑precision** – the heavy `left`/`right` tensors are stored as FP16 before the kernel; the kernel loads them as FP16, promotes to FP32 for accumulation, and writes FP32. This halves memory traffic while preserving numerical stability.

* **Tiling strategy** – the kernel tiles the output matrix in `BLOCK_M × BLOCK_N` (default 128×128). Inside each tile we stream over `BLOCK_K` elements of the reduction dimension. This matches the typical GEMM pattern used by Triton and exploits the high shared‑memory bandwidth of H100.

* **Head‑wise parallelism** – each `(batch, hidden)` pair is processed by an independent program‑id (`pid_head`). This yields `B * hidden_dim` independent GEMMs, perfectly fitting the GPU’s massive parallelism.

* **Mask handling** – masking is applied *before* the kernel in regular PyTorch (a cheap point‑wise multiplication). No extra branches are needed inside the kernel, keeping it simple and fast.

* **LayerNorm & Linear** – these are performed with PyTorch’s highly‑optimized fused kernels (`torch.nn.functional.layer_norm` and `torch.nn.functional.linear`), which already use CUDA kernels and are not a bottleneck compared to the O(N³) step.

The provided `custom_kernel` function conforms exactly to the required signature and runs entirely on the GPU, delivering a high‑performance forward pass for the TriMul operator.
